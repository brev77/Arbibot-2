## 1. Контекст

Цикл probe реагирует по расписанию: ~150 c обычный, ~20 мин после discovery-циклов.
Дислокация рождается в момент крупного свопа в тонком пуле; пока цикл дойдёт, окно могут
закрыть конкуренты или оно рассосётся (OVER-очереди жили 2–3 цикла — на грани слепой зоны).
Сырьевой тир (#57, live) закрыл слепую зону **по ширине** (335 кроссчейн-групп под
наблюдением); #58 закрывает её **по скорости**.

Верифицированные предпосылки (2026-08-18): eth_getLogs по адрес-листу ~100 пулов с
topic0-OR работает на платном BlockPi во всех 3 сетях за 0.1–0.35 c (0.2–0.4 MB на 5-мин
окно); ethers-ловушка — OR-форма `[[A,B]]`, а `[A,B]` = AND; V2-топик в смоук-окне был тих —
проверить живьём (DoD). Схема БД готова с миграции 058: `dry_run_run_stats.source
('cycle'|'event')` + синтетические `run_id = 'event-<uuid>'` (NOT NULL сохранён).

## 2. Как это работает — простыми словами

Отдельный таймер (в том же процессе probe, не отдельный сервис) каждые 30 секунд спрашивает
у цепи: «были ли за последние блоки крупные Swap-события по живым пулам подключённых бирж?»
Крупный = не меньше `max($500, 10% глубины пула)` в долларах — размер считается из самого
события и сырьевой цены токена. Если такой своп случился по токену, который торгуется в
двух и более сетях (не мажор — мажоры не квотируем по событиям), бот **сразу, не дожидаясь
цикла**, делает честную проверку этого токена: покупка на $50/$100 в дешёвой сети + продажа
в дорогой, минус газ обеих ног. Прибыльно — окно возможности открывается немедленно, с
пометкой «поймано событием» (`metadata.trigger='event'`). Ограничители: не больше 60
внеплановых проверок в час, один токен не чаще раза в 2 минуты, приоритет — открытые окна и
новорождённые пулы; общий RPC-guard #56 распространяется и на события.

## 4. Детализация

### 4.1. Конфиг (`probe-config.json`, блок `event`)

```json
"event": {
  "enabled": false,
  "pollSeconds": 30,
  "chunkAddrs": 150,
  "minSwapUsd": 500,
  "depthFraction": 0.10,
  "maxQuotesPerHour": 60,
  "tokenCooldownSec": 120
}
```

`enabled: false` на деплое; включается после полного alive-смоука (DoD-1).

### 4.2. Механика (по шагам)

1. **Event poller** — `setInterval(pollSeconds)` в процессе probe (не unref — как основной
   цикл). Состояние: `lastPolledBlock` на сеть. Живые пула — тот же alive-запрос, что у
   сырьевого тира (кэш на poll-цикл); адрес-лист чанкуется по `chunkAddrs` (100–200).
2. **getLogs**: `topics: [[SWAP_V3, SWAP_V2]]`, окно `lastPolledBlock..latest`, пагинация
   ≤5K блоков (верифицировано). При ошибке чанка — бисекция (паттерн #57).
3. **Фильтр крупных свопов** (чистая функция, юнит-тестируемая): `swapUsd = |amount| ×
   rawMarginalPrice` (последняя цена из `dry_run_raw_token_prices`; нет цены → пропуск);
   крупный ⇔ `swapUsd ≥ max(minSwapUsd, depthFraction × depthUsd пула)`.
4. **Гейты токена**: кроссчейн-группа (Set адресов из сырьевых групп, обновляется raw-проходом);
   НЕ canonical (мажорные свопы — нормальный рынок, не дислокация); cooldown
   `tokenCooldownSec`; скользящий кап `maxQuotesPerHour`; приоритет при выборе из очереди —
   открытые окна → newborn → прочие.
5. **Немедленная квота вне цикла**: оба направления, `phase2`-нотионалы 50/100, ноги через
   существующие `quoteUsdToUnitsBest`/`quoteUnitsToUsdBest`, газ — сглаженный сэмпл сети;
   расчёт `exec_pp` → INSERT в `dry_run_cross_chain_observations` с `run_id='event-<uuid>'`,
   `metadata.trigger='event'`.
6. **Окно сразу**: после event-квоты вызывается `runStage3Opportunities(eventRunId)`
   (чистый SQL — открытие/продление окна не ждёт цикла).
7. **Телеметрия**: строка в `dry_run_run_stats` с `source='event'`, `rpc_calls` и
   `cycle_ms` = длительность обработки пачки событий; RPC-guard учитывает event-вызовы.

### 4.3. Латентность (бюджет ≤60 c)

poll-интервал 30 c (в среднем 15 c до обнаружения) + getLogs 0.3–2 c + квота 2–5 c +
Stage 3 <1 c → типично **~20 c**, худший случай ~40 c — с запасом внутри DoD.

### 4.4. Шаги реализации

1. Чистые функции в `probe-pp-core.mjs` (фильтр крупных свопов, cooldown/кап) + тесты.
2. Event poller + гейты + немедленная квота + Stage 3 вызов + run_stats('event').
3. Локальные тесты (`node --test tools/`), деплой с `enabled:false`.
4. Полный alive-смоук на сервере → включение `enabled:true` → живая верификация DoD.

### DoD

- [ ] **Полный alive-смоук** (условие Hermes): getLogs по ВСЕМ живым адресам 3 сетей чанками
      100–200 — каждый чанк ≤5 c, суммарно укладывается в poll-окно; V2-топик подтверждён
      живьём (в прошлом смоуке V2-окно было тихим).
- [ ] Синтетический тест: фикстура лога крупного свопа кроссчейн-токена → квота вне цикла,
      `metadata.trigger='event'`, cc-obs строка с `event-<uuid>`, run_stats `source='event'`.
- [ ] Латентность «событие → квота» ≤60 c на живом стенде (замер по логам).
- [ ] Кап 60/час и cooldown 120 c соблюдаются (юнит-тесты + симуляция бурста).
- [ ] Фильтр «крупный» своп: юнит-тесты порога `max(minSwapUsd, depthFraction × depth)`.
- [ ] Canonical-группы не квотируются по событиям (фикстура).
- [ ] RPC-guard охватывает event-вызовы; `guard_fired` не растёт выше фона.
- [ ] `enabled:false` — поведение идентично текущему (регресс-гейт).

## 5. Риски и митигации

| Риск | Митигация |
|---|---|
| Потолки BlockPi по числу адресов/размеру ответа на полном множестве | полный alive-смоук ДО включения (DoD-1); чанки 100–200 + бисекция |
| Бурсты скам-свопов выжигают квот-бюджет | кап 60/ч + cooldown + кроссчейн-гейт + не-canonical + raw-цена как гейт валидности |
| Ложные срабатывания на стейбл-пулax | canonical-группы исключены из event-квот |
| Нагрузка поверх цикла | RPC-guard #56 суммарный; телеметрия по source в run_stats |
| Тихий V2-топик (не поймали живьём) | отдельный пункт DoD-1 |

## 6. Что план НЕ покрывает

- WebSocket-подписки (push вместо poll) — следующая итерация, если poll-латентности не хватит.
- Event-триггеры для intra-chain (Phase 1) — вне скоупа (стратегия межсетевая).
- Исполнение — как и весь PLAN14, только поиск и фиксация.
